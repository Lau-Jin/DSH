dsh-session-index 操作使用手册

完全化的 MCP 插件：一条命令安装，之后自动配置、自动建索引、新会话由文件事件自动识别（无需重启 DSH）、索引变更主动通知客户端，并自动生成可分发插件包与技能包。零第三方依赖，源会话只读。

1. 这是什么

它是一个 MCP (stdio) 插件。DSH 通过内置 dsh-mcp-client 连接它，Agent 就能用 13 个工具查历史。插件自带 install.mjs，自动把连接写进 DSH 配置，不需要手工填表或改 YAML；plugin.json 是机器可读能力清单，dist/*.zip 是可分发包。

DSH  ~/.dsh/sessions/**/session.v4.jsonl.zstd   (分帧 zstd)
WorkBuddy  ~/.workbuddy/projects/<工作区>/<会话id>.jsonl
        │  fs.watch 事件 → 防抖 → 后台子进程增量构建
        ▼
~/.dsh/session-index/   meta / cards / notes / vectors / <id>.jsonl.gz
        │  MCP stdio (JSON-RPC 2.0)
        ▼  13 tools + 4 prompts + 7 resources + 1 模板 + instructions + listChanged
        │
        ▼  DSH / WorkBuddy 里的 Agent
关键收益：原始会话约 55 MB 且分帧压缩，直接读要反复解压。建一次索引约 10 秒，之后新会话由事件驱动约数十毫秒纳入；查询只读派生索引并返回片段，不重复读源文件。

2. 安装（只需一次）

仓库 Lau-Jin/DSH 已转为公开仓库，根目录就是插件根，且已声明 dsh.bundle.patch，所以有三种装法。日常推荐第一种：不碰命令行。

方式 A：DSH 插件页（推荐 · 零命令行）

仓库地址：https://github.com/Lau-Jin/DSH

打开 DSH → 插件页 → 粘贴上面的地址 → 点安装 → 按提示完全退出 DSH 再打开。装完即可用，不用改配置、不用跑脚本。

插件包里的 cordis.patch.yml 会随 bundle 自动应用，挂两行：

行 id包作用
session-index-hostdsh-session-index宿主半身 lib/index.mjs：用 import.meta.url 拿到真实安装目录，把 server.mjs 绝对路径写进 ~/.dsh/session-index/server-path.txt
mcp-session-index@deepseek-ai/dsh-mcp-clientMCP stdio 客户端：13 工具 / 4 提示词 / 8 资源
为什么它自己认得路径？cordis.patch.yml 里的 command、args、DSH_HOME 三处都是 !!js 表达式，在 DSH 加载配置时求值（不是安装时），按「显式环境变量 → 宿主记下的路径文件 → profile 标准安装位置」依次探测。宿主行排在 MCP 行之前，路径文件先落盘，MCP 首次 spawn 就能命中——一次重启即生效。

方式 B：clone + 一键脚本（想自己控制目录 / 离线分发）

git clone https://github.com/Lau-Jin/DSH.git
cd DSH
install.cmd          # Windows 可直接双击；macOS / Linux / Git Bash 用 ./install.sh

脚本只是包装，实际执行 node install.mjs。它会先判断 profile 是否已以 bundle 方式注册了本插件：

  • 已注册（你从插件页装过）→ 不写 profile 配置，只清掉残留旧配置块，避免出现两条同 id 的 MCP 行；
  • 未注册（纯 clone 用户）→ 备份并幂等写入 ~/.dsh/profiles/desktop/cordis.patch.yml 的标记块。

两种情况都会：写 server-path.txt → 装 Skill → 开启自动维护 → 生成插件包与技能包 → 打印 6 项校验。

若 DSH 正在运行且工具列表未刷新，完全退出 DSH 桌面端再打开（最小化无效）。之后日常使用不需要任何命令行，新会话也无需重启。

换机器 / 换目录

索引产物固定在 ~/.dsh/session-index，与代码目录分离。因此把仓库 clone 到任意位置再跑一次安装即可，历史索引不会丢。插件页安装更省事：路径由运行时探测，换目录后重启就自动跟上。

手动备选：直接写配置（一般不用，仅排障） 
- id: mcp-session-index
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: session-index
    transport: stdio
    command: 'C:\Users\你\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
    args: [ 'D:\DSH\server.mjs' ]
    env: {}

手写时 command 必须是真正的 node.exe，不能填 Electron 主程序（DeepSeek Harness.exe）。Windows 路径放进 YAML 单引号里。方式 A / B 已自动处理这些。

3. 新会话免重启识别

这是 v2.2.0 引入、v2.4.0 沿用的核心能力：新会话产生后不需要重启 DSH，也不需要等定时轮询。

文件事件监听fs.watch(recursive) 监听 DSH 与 WorkBuddy 会话目录，写入事件防抖 3.5 秒后触发后台增量构建。
全新会话立即纳入静止期只作用于「已有索引且正在写入」的旧会话；新会话第一次发现就建索引，避免被永久跳过。
调用前即时检查每次工具调用前做轻量 stat 扫描，发现变化立即触发（10 秒节流），不等定时器。
主动通知客户端索引确有更新时发送 resources/prompts list_changed（30 秒节流），MCP 客户端自动刷新上下文。

实测：写入新会话 → fs-event 触发 → 重建 1 个 / 70ms → 发出通知 → list/search 立即可查，全程未重启。默认静止期 6000 下同样通过。

状态字段（session_index_status → autoIndex）

字段含义
watch.watching / watch.events已监听目录数 / 累计文件事件数
watch.lastEventAt / lastTriggeredAt最近事件 / 最近触发构建时间
lastResult.reasonfs-event / on-demand / interval / startup-refresh
notifications已发送的客户端通知次数
runs / failures / lastError累计构建、失败与最近错误
若平台不支持递归监听（权限/旧内核），监听会静默失败，60 秒定时轮询自动兜底，功能不受影响。

插件形态

文件 / 机制作用

自动打包（无需手工压缩）

lib/pack.mjs 是纯 Node 零依赖 ZIP writer（DEFLATE + CRC32 + 中央目录），不引入 archiver/jszip。安装时自动生成，也可随时重打：

node pack.mjs                # 生成两种包
node pack.mjs skill          # 只打技能包
node pack.mjs status         # 查看已生成包
node pack.mjs verify         # 校验 zip 结构
session_index_package { "mode": "all" }   # MCP 工具，Agent 也能触发
包内容用途
dsh-session-index-v2.4.1.zip全部源码 + plugin.json + README + 手册 + SKILL.md + 一键脚本 + MANIFEST.json + INSTALL.md完整分发 / 迁移到另一台机器
session-index-skill-v2.4.1.zip根 SKILL.md + README + MANIFEST（3 文件）直接导入 DSH「MCP 与技能」→ Skills
打包器自动排除所有会话索引分片、meta/cards/notes/vectors.json、备份、临时文件与已有 zip，并用系统解压工具验证过：包内 0 个敏感文件，可安全分发。接收方解压后运行 node install.mjs 即完成安装。

5. 可写入长期记忆

会话卡是历史的只读摘要；长期记忆是主动写入的结论，跨会话持久保存，brief 与语义搜索自动召回。存 notes.json，写前备份、原子写入。

type用途
decision / fact已定方案 / 客观事实
preference / todo偏好约定 / 待办
pitfall / note踩过的坑 / 其它（默认）
session_index_remember { "text": "TokenHub 通用 Key 用 /v1，maxTokens 必须 8192",
  "type": "decision", "tags": ["tokenhub"], "importance": 5 }
session_index_recall  { "query": "TokenHub", "limit": 5 }
session_index_forget  { "id": "n-xxxx" }                 // 归档，可恢复
session_index_forget  { "id": "n-xxxx", "purge": true }  // 物理删除

相同文本+类型自动合并；召回按相关度 + 重要度 + 新鲜度排序。

6. 跨应用统一索引

app数据位置格式
dsh~/.dsh/sessions/**/session.v4.jsonl.zstd上千独立 zstd 帧拼接
workbuddy~/.workbuddy/projects/<工作区>/<会话id>.jsonlmessage / function_call / ai-title

WorkBuddy 适配器取 aiTitle 作标题、剥除注入块但保留真实提问；id 加 wb: 前缀。所有工具支持 app 过滤，关联可跨应用。

session_index_list    { "app": "workbuddy" }
session_index_search  { "query": "插件", "app": "workbuddy" }
session_index_related { "sessionId": "wb:3aa3ea8d", "app": "all" }

7. 语义检索

默认 semantic：18 组中英同义扩展 → 候选召回 → 只在候选集上 BM25 重排，纯本地零 token；结果标注 matchType: exact | expanded。

mode行为
semantic（默认）同义扩展 + BM25
keyword所有词 AND 子串，精确查报错码/路径
hybrid / vector叠加可选向量；未配置 embedding 自动降级为 semantic
session_index_search { "query": "插件报错怎么修", "limit": 8 }
session_index_search { "query": "402 401008", "mode": "keyword" }

只返回命中片段（默认每条约 360 字），total 只是计数，不灌全文。

13. 故障排查、安全与回滚

现象处理
工具列表没出现 / 不是 13 个完全退出 DSH 再打开；或 node install.mjs --verify
新会话查不到等 3~5 秒（事件防抖）；status 看 autoIndex.watch.events 与 lastResult.reason；仍不行手动 refresh
监听未建立（watch.watching=0）平台不支持递归监听，60 秒轮询自动兜底；也可用 SESSION_INDEX_WATCH=0 明确关闭
「索引正在后台自动构建」首次启动正常现象，等待几秒
自动刷新没生效看 autoIndex.enabled/failures/lastError，确认 SESSION_INDEX_AUTO 不是 0
打包失败 / zip 打不开node pack.mjs verify 校验；包由纯 Node ZIP writer 生成，已用系统解压工具验证
prompts/resources 看不到客户端可能只实现 tools；Skill 自动兜底，工具不受影响
语义结果太宽泛用 mode: "keyword" 或调小 limit，看 matchType
hybrid 返回 degraded正常：未配置 embedding 自动降级
插件页提示「没有写入权限，无法安装」这不是权限问题，是 pnpm 那一步失败后的归类标签；先跑 node install.mjs --doctor 定位真因
安装卡住 / UND_ERR_DESTROYED、UND_ERR_INVALID_ARG见下方「插件页装不上」三节

插件页装不上？先体检

DSH 插件页装任何东西，底层都是一次 pnpm install。装不上时先跑只读体检，七项检查各自给出结论和修法：

node install.mjs --doctor
检查项会导致的现象
Node 支持 zstd索引建不起来
git 全局 URL 重写走第三方镜像时 codeload 返回 403 / 认证失败
pnpm fetch-timeout超过 60000 会让 pnpm 11 直接抛 UND_ERR_INVALID_ARG，所有安装失败
远端 git 依赖每次安装都要重下，大仓库必然超时
lockfile 残留 git+ssh仓库已删 / 缺 SSH key 时必失败
bundle 是否注册插件没被 DSH 加载
索引状态装完但没建索引

三个已确认的坑（2026-11-13 实测）

  1. fetch-timeout 有硬上限。pnpm 11.28 + undici 在 fetch-timeout > 60000 时直接报 UND_ERR_INVALID_ARG（60000 正常、65000 就失败）。调大超时不但没用，还会让所有安装全挂，所以 profile 的 .npmrc 里不要写这一项。
  2. 大 tarball 装不完。GitHub 直连实测 70–350 KB/s，28 MB 的包要数分钟，永远过不了 60 秒上限，于是不断 UND_ERR_DESTROYED 重试直到失败。正解是把它本地化：把包复制到本地目录，依赖写成 "pkg": "link:D:\\tools\\pkg"，之后安装完全离线（实测整份 profile 8 秒装完）。
  3. insteadOf 镜像规则会连坐。url.https://<镜像>/https://github.com/.insteadOf 会重写所有 GitHub HTTPS 地址，而镜像通常不代理 codeload.github.com（返回 403）。直连可用时建议去掉。
# 1) 先看有没有镜像重写规则
git config --global --get-regexp "url\..*\.insteadof"

# 2) 有的话去掉（直连可用时）
git config --global --unset-all "url.https://<镜像前缀>.insteadOf"

# 3) 把远端大依赖本地化（复制包 → link → 离线重建 lockfile）
#    改 package.json: "某包": "link:D:\\tools\\某包"
cd ~/.dsh/profiles/desktop
pnpm install --offline --frozen-lockfile --config.autoInstallPeers=false
本次修复的实际结果：profile 的 7 个依赖里 6 个为本地 link:、1 个来自 registry，零远端 git 依赖；离线整装 2.8 秒，真实 profile 同步 8.3 秒。之后从插件页装任意仓库，只需下载那一个新包。

安全与回滚

  • 索引含会话全文，只落在本机 ~/.dsh/session-index/，不要打包分享；分发包已自动排除这些数据。
  • 源会话（DSH / WorkBuddy）全程只读。install.mjs 写配置前自动备份，只改带标记整段，幂等可回滚。
  • forget 默认归档不删除；notes.json 写前留备份。
node install.mjs --uninstall      // 移除配置段与自动装的 Skill（先备份）
完全退出 DSH 再打开
可选：删除 ~/.dsh/session-index/ 与 dist/（不影响任何原始会话）
